一个项目在上线前，安全和质量风险从哪里来？我认为有四个来源，每个来源对应一类防线。

风险来源	                    具体例子	                                对应防线
你自己写的代码有缺陷	        SQL 注入、XSS、把客户端入参当可信数据	    静态分析（CodeQL、Semgrep）
你引入的第三方代码有问题	    依赖有已知漏洞，或被投毒	                依赖审查、audit、Dependabot
机密信息被提交	            OpenRouter key、数据库连接串进了 git 历史	密钥扫描（Gitleaks）
代码根本不能正常工作	        类型错误、构建失败、格式混乱	                lint、tsc、build

还有第五类，工具解决不了：鉴权逻辑漏洞和业务逻辑错误。


只格式化一个文件
pnpm prettier --write filepath

自查是否泄露密钥
git log --all --oneline -- .env .env.local





依赖版本管理规则压缩成一句话

选版本 = 在声明范围里选一个满足条件的，能复用 lockfile 里已有的就复用；update 某包 会重新解析那个包下面的整棵子树；dedupe 是主动去重。

据此判断该用哪个：

情况	                                                用什么
子依赖的范围仍然包含旧版本（如 firecrawl 的 zod）	        更新后再 pnpm dedupe
子依赖的范围不再包含旧版本（如新版 shadcn 的 zod）	    更新父包就够了，旧版本自然被清掉
父包的所有版本都不支持新版本	                            才考虑 overrides 或登记忽略
